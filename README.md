# NotaryMindAI — Historical Document Archive Processing Platform

> **Extract, transcribe, and structure genealogical and notarial records from historical manuscripts using GenAI with paleographic accuracy.**

**Current Version:** 2.0 (Project-centric architecture)  
**Status:** ✅ Production-ready for multi-project archive management  
**Language:** 🇬🇧 English (all documentation, code, and UI)  

---

## 🎯 What Is NotaryMindAI?

NotaryMindAI is a modular system for digitizing and structuring historical documents (primarily genealogical and notarial records) using:

- 📷 **Image Processing**: High-quality scans of historical manuscripts
- 🧠 **GenAI OCR**: Claude Opus 4.8 for paleographic transcription
- 🗂️ **Data Structure**: Standardized JSON schema (v2.0) for genealogical relationships and property data
- 🔍 **Validation**: Automated consistency checks (no duplicate vendors, valid genealogical chains, etc.)
- 📊 **Visualization**: Interactive graph viewer for relationships and property networks

**Key Use Cases:**
- ✅ Genealogical research (family trees, lineages, inheritance)
- ✅ Notarial archives (property deeds, wills, donations)
- ✅ Administrative records (official decisions, registrations)
- ✅ Heritage preservation (museum catalogs, archive digitization)

## 🏗️ Architecture: Project-Centric + Agnostic Tools

The system separates **project-specific data** from **reusable tools**, enabling you to manage multiple archives with one codebase.

### Directory Structure

```
NotaryMindAi/
│
├── README.md                        (this file)
├── SKILL.md                         (GenAI workflows & prompts)
│
├── projects/                        🔑 PROJECT-SPECIFIC CONTENT
│   └── <project-name>/              Example: any genealogical archive
│       ├── imported/                Raw image scans (.jpg, ~2000x3000px)
│       ├── metadata/                Per-image OCR output (1 JSON per image)
│       ├── GLOSSARIO.md             Project-specific normalization rules
│       ├── docs_logical.json        **Source of truth** (consolidated data generated by build_docs_logical.py)
│       └── docs_logical_map.json    Logical document mapping (AI generated)
│
├── skills/                          🔑 AGNOSTIC TOOLS
│   └── transcript/                Transcription pipeline (reusable)
│       ├── SKILL.md                 Workflow documentation
│       ├── SCHEMA.md                Data contract
│       ├── build_docs_logical.py    Build orchestrator
│       ├── find_new_docs.ts         Find pending images
│       └── validate_map.py          Validate project integrity
│
└── ui/                              🔑 AGNOSTIC VIEWER
    ├── main.html            Interactive graph browser
    └── SKILL.md                     Viewer documentation
```

### Key Design Principles

| Principle | Implication |
|-----------|------------|
| **Project-Centric Data** | Each archive lives in `projects/<name>/` with its own metadata and rules |
| **Agnostic Tools** | Build, validation, and UI work for ANY project (zero hardcoded data) |
| **Immutable OCR Output** | `metadata/*.json` files = source OCR, never hand-edited |
| **Declarative Mapping** | All project-specific logic in data files (`docs_logical_map.json`, `GLOSSARIO.md`) |
| **Single Source of Truth** | `docs_logical.json` is the consolidated, validated output |
| **Schema-Versioned** | Data contract in `SCHEMA.md` ensures forward/backward compatibility |

## 🚀 Quick Start: Process Your First Archive

### 1. Create a Project

```bash
mkdir -p projects/my-archive/{imported,metadata}

cat > projects/my-archive/docs_logical_map.json << 'EOF'
{
  "name": "My Archive",
  "description": "Description here",
  "documentos": []
}
EOF
```

### 2. Add Images

```bash
cp ~/my-scans/*.jpg projects/my-archive/imported/
```

### 3. List Pending Work

```bash
bun skills/transcript/find_new_docs.ts projects/my-archive
# Output: which images need OCR transcription
```

### 4. Process Images (GenAI)

For each pending raw image or pdf:
- Use Claude Opus 4.8 (required for accuracy)
- Apply prompts from `skills/transcript/SKILL.md`
- Save result to `projects/my-archive/metadata/<image-name>.json`
- Folow schema rules
 - Use `projects/my-archive/GLOSSARIO.md` to guide GenAI

### 5. Update Document Map

Edit `projects/my-archive/docs_logical_map.json`:
- Group metadata files into logical documents
- Define titles and types
- Add transaction info (buyers, sellers, values)
- Follow schema rules
- Use `projects/my-archive/GLOSSARIO.md` to guide GenAI
 
### 6. Build Consolidated Output

```bash
python3 skills/transcript/build_docs_logical.py projects/my-archive
# Generates: projects/my-archive/docs_logical.json
```

### 7. Validate

```bash
python3 skills/transcript/validate_map.py projects/my-archive
# Checks for errors, inconsistencies
```

### 8. View Results

```bash
cd NotaryMindAi
python3 -m http.server 8000
# Open: http://localhost:8000/ui/main.html?project=my-archive
```

### Processing Step 1: OCR via GenAI
```
GenAI reads image or PDF + GLOSSARIO.md
        ↓
Creates metadata JSON (full_transcript + entities + persons + relations)
        ↓
Saves to: projects/my-archive/metadata/page_0001.json
```

**Metadata structure:** See `skills/transcript/SCHEMA.md` for complete field reference, examples, and data contract.

**Input formats:** `.jpg`, `.jpeg`, `.png` (images), `.pdf` (PDF documents)

**Key fields in metadata JSON:**
- `persons[]` — People mentioned (roles, variants, confidence)
- `relations[]` — Relationships (genealogical, economic, legal, etc.)
- `properties[]` — Land/property descriptions
- `entities{}` — Extracted names, dates, places, values
- `full_transcript` — Complete OCR text from image

### Processing Step 2: Logical Document Mapping
Edit `projects/my-archive/docs_logical_map.json` to:
- Group images/PDFs into logical documents
- Define titles and types
- Add transaction info (buyers, sellers, values)

For detailed schema and examples → See `skills/transcript/SCHEMA.md`.

### Processing Step 3: Consolidation & Normalization
```bash
build_docs_logical.py
        ↓
Reads:  docs_logical_map.json + metadata/*.json + GLOSSARIO.md
        ↓
Applies: Normalization, variant resolution, relation inference
        ↓
Outputs: docs_logical.json (single source of truth)
```

**Output schema:** See `skills/transcript/SCHEMA.md` for complete structure, fields, and validation rules.

### Step 4: Visualization
```
main.html reads docs_logical.json
        ↓
Renders:  Genealogy graph + property network
        ↓
User:     Explores relationships, views images, drills down to sources
```

## 🎓 Processing Modes

### Mode A: Create/Reprocess Image JSON
**When:** New images or complete retranscription needed  
**How:** GenAI reads image + GLOSSARIO.md → generates `metadata/<name>.json`  
**Tools:** Claude Opus 4.8 + prompts from `SKILL.md`  
**Result:** Per-image JSON with transcription, entities, genealogy

### Mode B: Update Glossary
**When:** Normalization rules need adjustment  
**How:** Edit `GLOSSARIO.md` and regenerate  
**Note:** Never modifies source files, applied in-memory only  
**Result:** Consistent naming across all documents

### Mode C: Update Logical Document Map
**When:** Document groupings or transactions need updating  
**How:** Edit `docs_logical_map.json` (GenAI can help)  
**Note:** No re-OCR needed, just reorganization  
**Result:** Updated `docs_logical.json` with correct groupings

## ✅ Quality Checklist

Before delivering a project:

- [ ] All images in `imported/` have corresponding `metadata/` JSON
- [ ] All persons have roles captured
- [ ] All relations have source marking (explicit|inferred)
- [ ] Inferred relations marked with `inferedbyai: true` + confidence + reasoning
- [ ] Variant grouping for persons with confidence levels
- [ ] Dates normalized to YYYY-MM-DD with precision metadata
- [ ] No invented data (only [?] for uncertainty or empty)
- [ ] Transaction labels extracted from document text
- [ ] JSON validates: `jq empty docs_logical.json`
- [ ] Validation passes: `python3 skills/transcript/validate_map.py projects/<name>`
- [ ] UI loads and displays graph content

## 🔐 Non-Negotiable Rules

1. **Always ask before modifying existing data**
   - Show the user your plan
   - Wait for explicit confirmation
   - Never make silent changes

2. **Never invent data**
   - If uncertain, mark with [?]
   - If illegible, mark with [ilegível]
   - Leave fields empty rather than guess

3. **Metadata JSON is immutable**
   - Only changes via GenAI reprocessing (ask first!)
   - Follows fixed schema (v2.0)
   - Use GLOSSARIO.md for corrections, not editing JSON

4. **Use correct model for OCR**
   - **Required:** `github-copilot/claude-opus-4.8`
   - Weak models produce poor transcriptions
   - Ask before proceeding if model isn't right

5. **Single source of truth**
   - Always read from `docs_logical.json`
   - Never process raw images directly
   - All analysis flows through the consolidated output

## 🌍 Adapting to Other Contexts

### Genealogy Archives
- Focus on dates, filiations, inheritance chains
- Use `genealogia` block extensively
- Track variant spellings of names

### Notarial Archives
- Add `tipo_ato_jur` field (venda, herança, doação, etc.)
- Track buyers, sellers, values, dates
- Properties and confrontations

### Administrative Records
- Add `entidade_emissora` field
- Track decisions and effective dates
- Officials and signatures

### Museum/Heritage Collections
- Add `estado_conservacao` field
- Material description in `propriedades`
- Preservation notes in OCR metadata

## 🚨 Troubleshooting

| Issue | Solution |
|-------|----------|
| "Pending images found" | Run GenAI OCR (Mode A) on those images |
| "Validation error: invalid relation" | Check relation `attribute` field is valid; see SCHEMA.md |
| "JSON invalid" | Run `jq empty docs_logical.json` to see error |
| "Viewer not loading" | Check URL parameter: `?project=my-archive` |
| "Images not displaying" | Verify `imported/` directory exists and has JPGs/PDFs |
| "GLOSSARIO not applied" | Regenerate: `python3 skills/transcript/build_docs_logical.py projects/<name>` |
| "Variants not merged" | Add variant group to `projects/<name>/GLOSSARIO.md` and rebuild |
